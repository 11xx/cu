# Explicit browser playground

Run `cu playground` in a terminal and open its printed loopback URL in the
browser you intend to drive. No extension or grant is required. The server
serves only the packaged fixture, starts only on request, and runs in the
foreground until Ctrl-C. `--port 8765` selects a port; the default chooses a free
one. `--json` emits the launch descriptor for a caller that manages the process.

Use normal `cu observe`, frame capture, native input and outcome verification.
The page states two small tasks: replace and submit ordinary fields exactly
once, then continue with readiness and scrolling without replaying the first
submission. Reset starts a new trial; the visible task status and optional
receipt make incorrect values, repeated submission and incomplete follow-up
observable. Richer hover, obstruction and collection controls remain available.

For a cheaper-controller experiment, choose the controller or worker interface
explicitly; CU does not prescribe a coding-delegation mechanism. Give the worker the permitted task, exact window identity, recent evidence,
completion condition, tool/time bounds and exceptions. Send subsequent context
through the same retained worker when the selected interface supports it. Do not have CU select or
launch a model implicitly, and do not reduce CU capabilities to accommodate a
particular controller.

A native benchmark uses pixels and ordinary CU input, without extension DOM
reads, DevTools, fixture source reads or scripted page-state changes. The lead
checks the resulting visible task state. Compare equal outcomes across direct
execution, contextual follow-up and other explicitly selected model efforts.
Record failures and assistance instead of discarding failed runs.

Measure wall time, model/tool time where available, tokens, monetary cost and
reported subscription usage separately. Include lead setup/context work and
recovery in whole-task comparisons. Unknown billing or quota weighting remains
unknown; a page timer or token count is not an API invoice. Faster or more
reliable completion may justify greater cost. A preference for inexpensive
controllers changes the chosen route, not the available CU capabilities.

This is a synthetic usability playground. Collection counters do not certify
files on disk, and page readiness is not a real native chooser. The separate
complete-task fixture documents file verification; real browser/download and
model-cost comparisons need their own recorded trials.
